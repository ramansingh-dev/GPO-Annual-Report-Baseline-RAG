# Advanced RAG Challenge — Task 1

## Overview

This project implements a baseline Retrieval-Augmented Generation (RAG) pipeline using the GPO 2018 Annual Report.

Users can ask questions about the report. The application retrieves relevant passages from the document and uses a locally running language model to generate answers based on the retrieved context.

The project runs locally using Python, Ollama, and ChromaDB.

## Technology Stack

- **Python** — application logic
- **PyMuPDF** — PDF text extraction
- **ChromaDB** — vector storage and semantic retrieval
- **Ollama** — local AI model execution
- **qwen3-embedding:0.6b** — creates embeddings for document chunks and questions
- **qwen2.5:1.5b** — generates answers from retrieved context

## Prerequisites

- Python installed on your system
- Git
- Ollama installed and running

## Installation

### 1. Create and activate a virtual environment

On Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install Python dependencies

```powershell
python -m pip install -r requirements.txt
```

### 3. Download the required Ollama models

```powershell
ollama pull qwen3-embedding:0.6b
ollama pull qwen2.5:1.5b
```

Confirm that the models are available:

```powershell
ollama list
```

### 4. Place the source PDF

Place the GPO report at:

```text
data/GPO-Anual-report.pdf
```

The filename must match the path configured in `scripts/index_gpo.py`.

## Running the Application

Run these commands from the project root with the virtual environment activated.

### Step 1: Index the PDF

```powershell
python scripts/index_gpo.py
```

This process:

1. Extracts text and page numbers from the PDF.
2. Cleans and splits the extracted text into chunks.
3. Generates embeddings for the chunks.
4. Stores the chunks, vectors, and page metadata in ChromaDB.

The baseline index contains 153 chunks from the GPO report.

The indexing script rebuilds its GPO collection when run again.

### Step 2: Test semantic retrieval

```powershell
python scripts/search_gpo.py
```

Enter a question about the report.

The script displays the five most relevant chunks, their source page ranges, and their similarity distances. This helps verify retrieval independently of answer generation.

### Step 3: Ask questions

```powershell
python scripts/ask_gpo.py
```

Enter a question about the GPO report. The application retrieves relevant chunks, combines them into context, and sends the context and question to the language model.

The generated answer is printed in the terminal.

## RAG Pipeline

The application follows this workflow:

1. **Document ingestion:** Read the PDF and extract text.
2. **Chunking:** Clean the extracted text and divide it into smaller passages.
3. **Embedding:** Convert each document chunk into a numerical vector.
4. **Indexing:** Store the vectors, text, and page metadata in ChromaDB.
5. **Question embedding:** Convert the user's question into a vector using the same embedding model.
6. **Retrieval:** Search ChromaDB for the five most relevant chunks.
7. **Context construction:** Combine the retrieved passages with their source page information.
8. **Answer generation:** Ask the local language model to answer using the retrieved context.

## Example Questions

- How many depository libraries did GPO staff visit in FY 2018?
- What new digital system replaced FDsys, and when was it fully deployed?
- How much did GPO procure in printing and information products in FY 2018?

## Known Limitations

- The current chunking strategy is a baseline and may mix narrative text, headings, captions, or table content.
- Semantic retrieval may not rank the passage containing the complete answer first.
- Language model answers can be incomplete or incorrect even when relevant passages are retrieved.
- Page references help with verification, but generated answers must still be checked against the source document.
- This implementation is a command-line application; a graphical chat interface is not included.
- Advanced document-aware parsing, reranking, evaluation, and specialized handling of charts and tables are outside this baseline implementation.

## Reproducibility Notes

The ChromaDB index is generated locally from the PDF and is not required to be committed to Git. A developer can recreate it by placing the PDF at the expected path and running the indexing script.

The Python dependencies are listed in `requirements.txt`. Ollama must be installed separately, and the required models must be downloaded before running the application.
